# 中国语境下 IWRS / EDC（临床试验计算机化系统）的常见合规标准与细节要求

本文从“在中国开展药物/医疗器械临床试验时，使用 IWRS（中央随机化/药物供应）与 EDC（电子数据采集）系统”这一场景出发，整理监管侧普遍关注的法规、规范与落地要求，并给出可用于 URS/CSV 的要求清单。

不构成法律意见；具体适用范围仍需结合试验类型（药物/器械/IVD）、申办者/机构角色、数据出境、是否云部署、是否接入医院系统等进一步判定。

## 1. 监管与标准体系（中国为主，必要时引用国际通行方法）

### 1.1 临床试验质量规范（GCP）——对“电子系统”的直接要求来源

1) 药物临床试验质量管理规范（2020）  
核心关注：电子数据管理系统的“验证有效状态”、SOP 覆盖范围、稽查轨迹/原始数据保留、权限与安全、备份、盲态保持等。  
来源：国家药监局/国家卫健委《药物临床试验质量管理规范》原文（国务院公报）  
https://www.gov.cn/gongbao/content/2020/content_5525106.htm

2) 医疗器械临床试验质量管理规范（2022）  
核心关注：临床试验数据真实/准确/完整/可追溯，源数据更改需说明理由并签名与日期等（对电子化系统意味着：更改留痕、责任可归属、审计可追溯）。  
来源：国家药监局/国家卫健委《医疗器械临床试验质量管理规范》公告转载  
https://amr.hainan.gov.cn/himpa/yprz/zcfg/ylqx/202407/t20240728_3705206.html

### 1.2 数据完整性与电子记录管理——“怎么做稽查轨迹/权限/备份/电子签名”

国家药监局《药品记录与数据管理要求（试行）》（2020年第74号）  
核心关注：全过程信息真实、准确、完整、可追溯；电子记录需达到纸质同等功能；权限分离、用户唯一性、权限变更可追踪；记录/数据的采集处理存储检索报告全生命周期可控；备份与恢复等。  
来源（原文转载）：  
https://amr.hainan.gov.cn/himpa/yprz/zcfg/yp/202102/t20210219_2935820.html

### 1.3 电子签名的法律基础

若系统使用“电子签名/电子签署”作为质量体系证据的一部分，应遵循《中华人民共和国电子签名法》的等效性与可靠性要求；并在 CSV 中证明签署机制满足：签署人身份、签署意图、签署时间、签署后防抵赖/防篡改、签署记录可追溯。

### 1.4 网络安全与个人信息保护（医疗数据强相关）

在临床研究系统中，受试者信息、病历片段、检验结果等通常属于敏感个人信息，且医疗卫生行业对等保与数据安全有行业性要求。

- 《医疗卫生机构网络安全管理办法》（国家卫健委发布）强调落实等级保护（第三级及以上）、保护重要数据与个人信息等。  
来源：国家卫健委网站  
http://www.nhc.gov.cn/guihuaxxs/s10743/202208/50e2ef41b7554ae894053bcac32b79f0.shtml
- 网络安全等级保护 2.0：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》（常见落点：等保二级/三级测评与整改）
- 个人信息保护与数据安全：网络安全法、数据安全法、个人信息保护法（PIPL）
- 医疗数据安全参考标准（常见被引用）：GB/T 42430《信息安全技术 健康医疗数据安全指南》（注：落地时需结合数据分类分级、脱敏、访问控制、审计等）

## 2. 把法规“翻译成系统要求”：审评/核查常看的“证据点”

监管/稽查通常不问你有没有“资格证”，而问你能否提供“系统已验证 + 持续受控”的证据链。可拆成三类证据：

1) 功能证据：系统具备必要能力（权限、稽查轨迹、电子签名、备份、盲态控制、导出等）  
2) 过程证据：有 SOP/制度、培训记录、变更控制、事件处理、供应商管理、定期回顾  
3) 验证证据：CSV 文档 + 测试记录（IQ/OQ/PQ 或同等）+ 验证总结报告（VSR）

## 3. 计算机化系统验证（CSV）在中国项目中的通用落地方式

### 3.1 典型 CSV 交付物（可做审计/核查包）

- 系统边界与用途说明（System Description / Intended Use）
- URS：用户需求说明（含法规条款映射与风险分级）
- 风险评估（Risk Assessment，识别影响受试者安全/关键数据/盲态的风险）
- 设计与配置说明（如有，可含数据字典、权限矩阵、流程图）
- 测试方案与记录（可按 IQ/OQ/PQ 或按 SaaS/自研实际拆分）
- 偏差/缺陷与 CAPA（验证期间发现问题的纠正预防）
- 变更控制（Change Control）与版本发布记录
- 数据迁移/转换验证（如存在历史数据/系统切换）
- 备份与恢复演练记录、应急预案演练
- 周期性回顾（Periodic Review）与再验证策略

### 3.2 风险导向（Risk-based）要点

对 IWRS/EDC，通常被视为“高影响系统”，建议至少将以下列为高风险并重点测试：

- 盲态相关：揭盲、药物分配、随机化列表/种子、权限隔离
- 关键终点数据：关键 CRF 字段、派生计算、锁库前后变更
- 审计与可追溯：稽查轨迹是否完整且不可篡改、能否导出供稽查
- 安全与权限：唯一账号、最小权限、管理员与业务权限分离
- 数据导出：导出数据与源数据一致性（包含编码/字典/时间戳/版本）

## 4. 数据完整性（Data Integrity）与“可追溯性”的细化要求（落在产品里）

可用 ALCOA+ 思路形成系统要求清单（不需要写进 UI，但需要体现在机制与验证中）：

- 可归属（Attributable）：每条数据的创建/修改必须关联到唯一用户与其角色/机构
- 清晰可读（Legible）：记录内容、时间戳、签名意图、修改理由清晰
- 同步（Contemporaneous）：操作发生时即时记录（避免离线后补录造成时序不可信）
- 原始（Original）：保存原始值/原始版本；可提供核证副本（Certified Copy）策略
- 准确（Accurate）：校验规则、字典一致性、计算/派生可复现
- 完整/一致/持久/可获得（Complete/Consistent/Enduring/Available）：全生命周期留存、可检索、可导出、可恢复

对应产品能力通常体现为：稽查轨迹（Audit Trail）、版本化（Record Versioning）、变更理由（Reason for Change）、时间戳与时钟源管理、备份与恢复、导出一致性校验等。

## 5. EDC 系统常见“必备能力”清单（可直接作为 URS 条目骨架）

### 5.1 账户、权限与职责分离

- 唯一账号，不得共用账号；支持禁用/离职回收；密码策略与（可选）MFA
- RBAC：按申办者/CRO/中心/研究者/CRC/CRA/DM/统计/稽查/管理员等角色
- 权限矩阵可配置且有审批流程；权限变更可追踪与导出
- 管理员权限与业务审批/录入权限隔离（避免“既当裁判又当运动员”）

### 5.2 eCRF 设计与版本控制

- eCRF/访视/表单版本化；上线后版本变更需受控（影响评估、回滚策略）
- 字典/编码（例如选项值与显示分离）与数据字典输出
- Edit Check（范围/逻辑/一致性校验）、提示与阻断策略可配置

### 5.3 数据录入、修改、电子签名与稽查轨迹

- 数据录入：字段级必填、范围、格式、依赖、时间窗等控制
- 数据修改：必须记录谁/何时/改了什么/修改理由；保留原值
- 电子签名：签署意图（例如“数据录入完成/医生确认/锁库确认”）、签署时间、签署人身份；签后不可否认
- 稽查轨迹：覆盖数据、元数据与关键配置；可查询、可导出、可按条件过滤

### 5.4 质疑（Query）与数据管理流程

- Query 生命周期：提出→回复→关闭→重开；支持指派与时限
- SDV/SDR 标记与监查支持（按中心/受试者/访视/字段维度）
- 锁库（Database Lock）机制：冻结数据、限制变更、解锁需审批且留痕

### 5.5 数据导出与归档

- 导出：支持统计常用格式（如 CSV/SAS/SPSS）与导出日志；导出包含元数据（版本/字典/时间戳/审计信息）
- 数据一致性：导出数据与系统内数据一一对应、可复核
- 归档：试验结束后数据与配置可长期保存；支持恢复与检索

## 6. IWRS/IRT 系统常见“必备能力”清单

### 6.1 随机化与盲态控制

- 随机化方案配置与受控（分层、区组、中心、配比等）；变更需审批与验证
- 随机化列表/种子/算法实现受控（访问限制、版本化、可复现性证明）
- 揭盲：紧急揭盲与常规揭盲流程分离；权限受控；每次揭盲必须留痕并可导出

### 6.2 药物/器械供应与回收（如适用）

- 发放、回收、退回、销毁、库存与批次管理
- 药物责任链（Accountability）：谁在何时对哪个受试者发放了什么
- 异常处理：发放错误、更换、丢失、超温等偏差记录与 CAPA

### 6.3 与 EDC/CTMS 的接口与一致性

- 受试者状态在各系统之间的一致性（筛选/随机/入组/脱落）
- 接口数据校验、重放防护、接口审计与失败补偿

## 7. 安全与运维控制（“技术措施 + 管理措施”）

### 7.1 安全基线（常见被核查/等保测评关注点）

- 传输加密（TLS）、存储加密（含备份）、密钥管理
- 日志审计：登录、权限变更、数据变更、导出、揭盲、锁库等关键事件
- 最小权限与分权：应用管理员、数据库管理员、运维与业务审批分离
- 漏洞管理：依赖漏洞扫描、补丁策略、应急响应

### 7.2 备份、恢复与业务连续性

- 定期备份（含配置/数据库/审计日志）+ 异地或多副本策略
- 定期恢复演练（能证明“可恢复”而不是“有备份”）
- 灾备与 RPO/RTO 指标（按风险与业务重要性确定）

### 7.3 供应商与外包管理（云/第三方）

- 合同/质量协议明确责任边界（验证责任、数据所有权、审计支持）
- 第三方访问控制与最小授权
- 供应商变更通知与影响评估机制
