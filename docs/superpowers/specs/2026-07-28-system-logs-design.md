# 日志管理页面改版设计

日期：2026-07-28

## 背景

当前日志管理页存在两个问题：

1. 模拟数据时间过旧，默认筛选后首屏无有效数据，和“最近一周日志”的使用预期不一致。
2. 日志信息粒度偏粗，缺少合规审计场景需要的操作主体、操作对象、风险等级、终端环境与追踪信息，无法支持清晰追溯。

本次改版目标是让日志管理页首屏默认展示最近 7 天有效日志，并为每条日志提供清晰、结构化、可审计的详情信息。

## 目标

- 默认展示最近 7 天日志样本。
- 列表支持快速识别高风险、失败、关键操作。
- 点击单条日志后，通过右侧 `Drawer` 查看详细审计信息。
- 详情采用“公共审计字段 + 按类型扩展字段”的分类型定制结构。
- 本次先完成高质量 mock 数据与交互，不接真实接口。

## 非目标

- 不新增独立详情页。
- 不对接后端日志接口。
- 不扩展批量导出、下载原始日志、全文检索等高级能力。

## 页面结构

### 1. 顶部筛选区

保留当前筛选布局，字段调整为更贴近审计场景：

- 日志类型
- 模块
- 操作人
- 关键字
- 开始日期
- 结束日期

默认时间范围为最近 7 天，且 mock 数据全部落在该区间内。

### 2. 日志列表区

列表采用高密度管理后台表格，字段如下：

- 时间
- 类型
- 模块
- 操作人
- 动作
- IP / 终端
- 结果
- 风险等级
- 操作

交互规则：

- 首屏默认展示最近 7 天日志。
- 每行提供“查看详情”入口。
- 风险等级以低风险 / 中风险 / 高风险区分。
- 结果以成功 / 失败视觉区分。
- 高风险或失败日志采用更醒目的浅色行背景辅助识别。

### 3. 右侧详情抽屉

采用项目现有 `Drawer` 组件，保持管理后台风格，避免多层卡片嵌套。

抽屉头部信息：

- 标题：`对象名称/编号 + 审计详情`
- 副标题：`发生时间 + 操作人姓名/账号`

抽屉正文固定包含 4 个分组：

#### 事件摘要

- 日志编号
- 日志类型
- 所属模块
- 操作结果
- 风险等级
- 事件说明

#### 操作主体

- 操作账号
- 操作人姓名
- 角色
- 所属中心或部门

#### 操作对象

- 对象类型
- 对象标识
- 对象名称
- 关联编号

#### 环境与追踪

- IP 地址
- 浏览器 / 操作系统
- 请求时间
- Trace ID / 会话 ID
- 来源入口

## 分类型扩展字段

### 登录审计

在公共字段基础上增加：

- 登录方式
- 认证结果
- 失败原因
- 设备指纹或终端信息

### 数据操作日志

在公共字段基础上增加：

- 动作类型（新增 / 编辑 / 删除 / 导出 / 查看）
- 变更前后摘要
- 影响对象
- 关联患者 / 受试者 / 档案

### 系统日志

在公共字段基础上增加：

- 任务名称
- 服务模块
- 错误码
- 异常原因
- 重试状态

## 数据设计

日志数据结构分为两层：

1. 列表基础字段  
用于表格展示和筛选。

2. 详情字段  
用于抽屉展示，包含公共字段与按类型扩展字段。

mock 数据要求：

- 总量 8 到 12 条。
- 时间分布覆盖最近 7 天。
- 覆盖 3 类日志：登录审计、数据操作日志、系统日志。
- 覆盖成功、失败、低中高风险。
- 覆盖查看、编辑、删除、导出、登录等关键动作。

## 交互说明

- 点击表格“查看详情”打开右侧抽屉。
- 关闭抽屉后返回原列表上下文，不跳转页面。
- 重置筛选后回到最近 7 天默认区间。
- 当筛选结果为空时，提示“当前筛选条件下没有找到日志”，并支持恢复默认显示。

## 组件与实现边界

- 页面主文件：`src/pages/system/logs/index.tsx`
- 抽离日志类型、mock 数据、默认时间范围、辅助工具函数到同目录独立文件，降低页面复杂度。
- 使用现有 `Drawer` 组件承载详情展示。
- 尽量复用项目现有视觉风格：浅灰背景、白色面板、紧凑信息布局。

## 测试与验证

至少验证以下内容：

- 首屏默认展示最近 7 天 mock 数据。
- 重置筛选后仍显示最近 7 天数据。
- 不同日志类型可正常打开对应详情。
- 成功 / 失败、低 / 中 / 高风险展示正确。
- 构建通过，且本次变更文件 lint 无新增问题。

## 方案选择结论

本次最终采用：

- 列表 + 右侧详情抽屉的交互结构。
- 分类型定制详情方案。
- 最近 7 天 mock 数据口径。

该方案最接近目标截图效果，同时兼顾高密度列表浏览效率与审计详情的清晰呈现。
